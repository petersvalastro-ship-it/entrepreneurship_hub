01

Partner Correction

Mark one accurate answer with a star (★). Revise one answer that needs more precision.

Sample Answer — Example Only

Original: “A pain point is when something is bad.”

Revised: “A pain point is a specific problem a user has with cost, time, effort, quality, or frustration — for example, waiting 3 minutes to sharpen a pencil before class.”

02

Peer Feedback and Revision

Refer to the user, pain point, evidence, or a specific design feature. 'I like it' is not enough information for revision.

Sample Answer — Example Only

Glow: The sharpener in each table caddy directly fixes the long line, because four students can sharpen at once instead of one.

Question: What happens if a caddy sharpener breaks or gets full of shavings?

Grow: Add a simple “empty the shavings” job to the table roles so the sharpener keeps working all week.

Not specific enough: “It's cool, I like it.”

03

Revision Decision

Sample Answer — Example Only

Feedback we will use: Add a table job for emptying the shavings.

Why: It keeps the solution working after day one, which makes it more feasible.

Visible revision: We added a “Caddy Captain” label and a weekly checklist to our sketch.
